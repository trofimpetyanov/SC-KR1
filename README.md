# BankHSE

Финансовое приложение на SwiftUI с реализацией различных паттернов проектирования.

## Общая информация

BankHSE - это приложение для управления личными финансами, разработанное на SwiftUI. Приложение позволяет:
- Управлять банковскими счетами
- Создавать и категоризировать доходы и расходы
- Просматривать аналитику по доходам и расходам
- Экспортировать и импортировать данные в различных форматах

## Архитектура проекта

Приложение построено с использованием трехслойной архитектуры:
1. **Слой представления (Views)** - SwiftUI интерфейсы (`AccountsView`, `CategoriesView`, `OperationsView`, `AnalyticsView` и др.)
2. **Слой бизнес-логики (Facades, Commands)** - фасады и команды для реализации бизнес-логики
3. **Слой данных (Repositories, DataStore)** - хранение и управление данными

### Структура проекта

```
BankHSE/
├── Models/                    # Модели данных
├── Views/                     # UI компоненты
│   ├── Accounts/
│   ├── Categories/
│   ├── Operations/
│   └── Analytics/
├── DataHandling/              # Управление данными
│   ├── Storage/               # Хранение данных
│   ├── Repositories/          # Репозитории
│   └── Facades/               # Фасады
├── Factories/                 # Фабрики для создания моделей
├── Utils/                     # Вспомогательные классы
│   ├── DependencyInjection/   # DI контейнер и паттерны
│   ├── Export/                # Классы для экспорта/импорта
│   └── Formatters/            # Форматтеры для данных
└── Commands/                  # Команды
```

## Реализованные паттерны

### 1. Порождающие паттерны

#### Фабричный метод (Factory Method)
- **Расположение**: `BankHSE/Factories/`
- **Классы**: `AccountFactory`, `CategoryFactory`, `OperationFactory`
- **Описание**: Фабрики для создания и обновления экземпляров моделей с валидацией.

#### Singleton
- **Расположение**: `BankHSE/Utils/DependencyInjection/DIContainer.swift`
- **Класс**: `DIContainer`
- **Описание**: Синглтон для централизованного доступа к зависимостям.

### 2. Структурные паттерны

#### Фасад (Facade)
- **Расположение**: `BankHSE/DataHandling/Facades/`
- **Классы**: `AccountsFacade`, `CategoriesFacade`, `OperationsFacade`, `AnalyticsFacade`
- **Описание**: Фасады предоставляют унифицированный интерфейс для работы с подсистемами (репозиториями и фабриками).

#### Прокси (Proxy)
- **Расположение**: `BankHSE/DataHandling/Storage/DataStoreProxy.swift`
- **Класс**: `DataStoreProxy`
- **Описание**: Прокси для кэширования запросов к хранилищу данных.

#### Декоратор (Decorator)
- **Расположение**: `BankHSE/Utils/DependencyInjection/CommandPattern.swift`
- **Классы**: `TimeMeasurementDecorator`, `VoidTimeMeasurementDecorator`
- **Описание**: Декораторы для измерения времени выполнения команд.

### 3. Поведенческие паттерны

#### Команда (Command)
- **Расположение**: 
  - `BankHSE/Utils/DependencyInjection/CommandPattern.swift` - базовые интерфейсы
  - `BankHSE/Commands/` - конкретные реализации
- **Интерфейсы**: `Command`, `VoidCommand`
- **Классы**: `CreateAccountCommand`, `UpdateAccountCommand`, `DeleteAccountCommand`, и другие
- **Описание**: Паттерн команда для инкапсуляции логики в виде отдельных объектов.

#### Посетитель (Visitor)
- **Расположение**: `BankHSE/Utils/Export/DataExportPattern.swift`
- **Интерфейс**: `DataExportVisitor`
- **Классы**: `StringExportVisitor`, `CSVExportVisitor`, `JSONExportVisitor`
- **Описание**: Посетитель для экспорта данных в различные форматы.

#### Шаблонный метод (Template Method)
- **Расположение**: `BankHSE/Utils/Export/TemplateMethodPattern.swift`
- **Классы**: `DataImporter`, `JSONImporter`, `CSVImporter`
- **Описание**: Шаблонный метод для импорта данных из различных форматов.

## Как запустить и тестировать

1. Откройте проект в Xcode (версия 16 или выше)
2. Выберите симулятор iOS (iPhone или iPad)
3. Запустите приложение (⌘+R)

### Основные функции для тестирования

1. **Управление счетами**:
   - Создание нового счета: кнопка "+" на экране счетов
   - Редактирование счета: нажмите на счет в списке
   - Удаление счета: свайп влево по счету

2. **Управление категориями**:
   - Переключение между категориями доходов и расходов
   - Создание категории: кнопка "+" на экране категорий
   - Редактирование и удаление: аналогично счетам

3. **Операции**:
   - Добавление операции: кнопка "+" на экране операций
   - Выбор типа операции, счета, категории, суммы и даты
   - Просмотр списка операций

4. **Аналитика**:
   - Переключение между периодами (день, неделя, месяц, год)
   - Просмотр общей статистики и топ категорий

5. **Экспорт/Импорт**:
   - Откройте настройки и выберите "Импорт/Экспорт"
   - Выберите формат (YAML, JSON, CSV)
   - Экспортируйте данные и затем импортируйте их

## Особенности реализации и основные сценарии

### Dependency Injection
- DI контейнер упрощает тестирование и заменяемость компонентов
- Основные зависимости инициализируются в `DIContainer.swift`

### Обработка данных
- `LocalDataStore` обеспечивает хранение данных в UserDefaults
- `DataStoreProxy` предоставляет кэширование для оптимизации доступа к данным

### Командный паттерн
- Команды инкапсулируют действия пользователя
- Декораторы команд добавляют функциональность к базовым командам

### Экспорт/Импорт
- Используется паттерн Посетитель для обхода структур данных
- Шаблонный метод структурирует процесс импорта данных

## Тестирование паттернов

Для проверки работы паттернов рекомендуется выполнить следующие действия:

1. **Командный паттерн** - создание, обновление и удаление данных через UI
2. **Фасад** - взаимодействие с различными экранами приложения
3. **Посетитель** - экспорт данных в различные форматы
4. **Шаблонный метод** - импорт данных из файлов различных форматов
5. **Прокси** - создание нескольких операций и наблюдение за производительностью

## Заключение

Приложение демонстрирует использование различных паттернов проектирования в контексте реального приложения. Каждый паттерн выбран для решения определенных проблем и улучшения структуры кода.
